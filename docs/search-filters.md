# 横断検索 (#10)

`/search` の GET query に検索条件を保持する。`q` は制度名、別名、ロット名、出品タイトル、取引内容、移行、交換ルールを対象にする。保有ロットとロットなし口座残高を別々に集計し、残数ゼロは初期一覧に表示しない。無効な口座と制度も残高がある場合は初期一覧に表示し、`active_only=1` で除外する。

主な条件は `member[]`、`category`、`program`、`policy`、`restriction`、`expires_within`、`listing`、`transfer_status`。同時指定は AND 条件とする。名義内は OR 条件で複数名義と `shared`（家族共通）を同時選択でき、未選択なら全名義を対象とする。従来の `member=ID` / `member=shared` も受け付ける。`preset` は今すぐ対応、期限7/30日、方針未設定、売る予定・未出品、出品中・期限接近、移行予定日超過を提供する。ページングは `lots_page` と `accounts_page` を分離し、query を維持する。

キーワードはパラメータとして SQL に渡し、画面表示は Blade でエスケープする。絞り込み中は、期限などの条件を適用できない別ドメインの候補を混ぜない。移行状態を指定した場合は該当移行を別枠に表示する。

## 横断結果への条件適用 (#19)

名義・制度・カテゴリ・有効状態はロットと口座だけでなく、取引の口座、出品に含まれるロットの口座、移行ステップの移行元または移行先口座にも適用する。移行は同じステップの状態と、同じ端点口座の名義・制度・カテゴリがすべて一致した場合のみ表示する。異なるステップや端点の条件を組み合わせて一致した扱いにはしない。移行グループの名義は端点口座の代わりには使わない。

交換ルールは移行元または移行先の同じ制度に制度・カテゴリ・有効状態を適用する。ルールに名義はないため、名義指定時はルール候補を表示しない。方針・譲渡制限・期限・出品状態、およびロット専用プリセットを指定した場合も、これらの条件を適用できない取引・出品・移行・ルールの別枠は表示しない。`transfer_status` または予定日超過プリセットでは別枠を移行だけに限定する。

制度名・提供元・aliasはすべての結果で検索できる。取引では関連口座、出品では関連ロットの口座、移行ではステップ端点の口座、ルールでは移行元・先制度を参照する。

`include_history=1`（「消費済み・取消済み・残高ゼロも含める」）で消費済み・取消済みロットと取引履歴がある残高ゼロ口座も検索できる。初期一覧は従来どおり保有中だけを表示し、対応用プリセットのロットも保有中に限定する。

詳細リンクは現在の検索queryを `search[...]` として保持し、「検索結果へ戻る」で名義・履歴・ページ番号を含む条件へ戻れる。戻り先は固定の検索ルートを使う。条件チップの解除は該当条件とページ番号を除去し、全解除は検索queryをすべて消す。

キーワードだけの検索では、ロット未登録の出品下書きやステップ未登録の移行グループも従来どおりタイトル・目的・目標制度（aliasを含む）で検索できる。名義などの口座条件を指定した場合は、関連口座を解決できない下書きを除外する。
