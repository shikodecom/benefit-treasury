# アプリ内通知 (#11)

`php artisan benefit:notifications` を JST 基準で実行する。Laravel scheduler は毎日 8:00 JST にこのコマンドを起動する。運用環境では `php artisan schedule:run` を毎分実行する。

期限ロットは残数があるものに限り、30/14/7/3日前、当日、期限超過1/7/30日の段階で通知する。同じ段階と期限日は一意に記録する。日次実行が遅れた場合も、現在の段階を一つだけ生成する。`sell_now` で未出品なら未出品の文面、出品中なら価格見直しの文面に切り替え、通常の期限通知と重複させない。売れず終了した出品は残数がある場合に一度知らせる。

移行ステップは processing のみを対象に、着弾予定3日前・当日・超過1/7/30日の段階で通知する。期限や予定日を変更した場合は新しい `milestone_date` で通知でき、古い通知は履歴として保持する。対象の残数がゼロ、完了、取り消し、または日付変更済みなら一覧で「対応済み」と表示する。通知本文には口座ヒント、メモ、コード類を含めない。

`/notifications/preferences` では通知種別と各段階を個別に切り替える。メールと Push は利用しない。
